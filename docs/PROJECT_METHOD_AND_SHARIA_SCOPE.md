# توثيق نطاق المشروع ومنهجية التحليل (استخدام شخصي)

آخر مراجعة: 2026-10-18  
المستودع: `MedhatCoding/Egx-ai-analysis-`  
الغرض: مساعد بحث وتحليل شخصي للأسهم والصناديق المتوافقة مع الشريعة في البورصة المصرية، وليس خدمة توصيات عامة.

## 1. نطاق الأسهم المتوافقة مع الشريعة

يعمل الكون الافتراضي من `config.yaml` عبر `universe.mode: sharia_union`، ويجمع ثلاثة مصادر:

1. مكونات `data/egx33.txt` (مؤشر EGX33 المرجعي).
2. الرموز الموجودة في `data/sharia_extra.csv`، وهي قائمة إضافات خارج EGX33 مع مصدر تحقق وتاريخ مراجعة وحالة.
3. الرموز في `data/universe.csv`، وهي قائمة بحث مرجعية شخصية وليست بحد ذاتها إثباتًا للتوافق الشرعي.

**وجود سهم في قائمة البحث العامة لا يجعله مؤهلًا لتوصية شراء.** بوابة الشريعة في `src/pipeline.py` تسمح بإشارة BUY فقط إذا كان `sharia_verified=True`. المرشح الذي لا يملك اعتمادًا حديثًا يظل ظاهرًا للمراقبة مع سبب صريح، ولا يتحول إلى توصية شراء.

### قائمة الإضافات خارج المؤشر

ملف `data/sharia_extra.csv` يحتوي حاليًا على 73 سجلًا مصدرها المسجل في الملف:
`Boubyan Capital — Egypt Sharia Compliant Companies Q1 2026`، وتاريخ المراجعة المدخل هو 2026-06-08.

- حداثة الاعتماد مضبوطة حاليًا على 180 يومًا في `config.yaml`.
- بعد انتهاء المدة، لا يظل السهم الخارجي مؤهلًا تلقائيًا للشراء؛ يلزم إعادة التحقق وتحديث `verified_on` و`verification_source`.
- هذه القائمة ليست ضمانًا دائمًا للتوافق ولا حكمًا شرعيًا مستقلًا صادرًا عن التطبيق. يجب الالتزام بالمعيار الشرعي الذي تختاره ومراجعة المصدر الأصلي وأي تحديثات لاحقة.
- لا تُضف رمزًا إلى القائمة باعتباره متوافقًا لمجرد الاسم أو القطاع. سجّل مصدرًا قابلًا للمراجعة وتاريخ التحقق والحالة `approved`.
- عضوية EGX33 تُستخدم هنا باعتبارها تصنيف المؤشر الشرعي، مع ضرورة مراجعة قائمة مكوناته الرسمية كلما صدر تحديث للمؤشر.

### حقول `data/sharia_extra.csv`

| الحقل | المعنى |
|---|---|
| `code` | رمز السهم في بيانات المشروع |
| `name_ar` | اسم الشركة |
| `verification_source` | اسم المصدر الذي استُخدم للتحقق |
| `verified_on` | تاريخ آخر مراجعة بصيغة YYYY-MM-DD |
| `notes` | ملاحظات المراجعة أو ما يلزم التحقق منه |
| `status` | يجب أن تكون `approved` كي تدخل قائمة الإضافات |

## 2. أين تُنفّذ قواعد النطاق؟

- `src/universe.py`: يجمع القوائم، ويحسب حالة المراجعة وعمرها، ويحدد أهلية السهم.
- `src/pipeline.py`: يحفظ سجل الكون المستخدم في كل تشغيل في `data/signals/universe.csv`، ويطبع عدد الأسهم من كل مصدر، ويفرض بوابة الشريعة قبل نشر BUY.
- `src/portfolio.py`: يمنع توصية زيادة المركز إذا كان الأصل موسومًا صراحةً بأنه غير موثق شرعيًا.
- `config.yaml`: يحدد وضع الكون، ومدة صلاحية المراجعة، وفترة التاريخ المطلوبة، وحدود المخاطر وخصائص ML.
- `tests/test_engine.py`: اختبارات دون اتصال لاستهلاك بيانات اصطناعية، بما فيها مسارات أهلية الشريعة والاختبار المتكامل.

## 3. البيانات التاريخية

الإعداد الحالي يطلب حتى **8 سنوات** من التاريخ حيث يتيح مزود البيانات ذلك. هذا طلب جلب وليس ضمانًا بأن كل سهم لديه 8 سنوات من البيانات.

- المصدر الأساسي للأسعار التاريخية: Yahoo Finance عبر لاحقة الرموز المصرية المحددة في الإعداد.
- المصدر الاحتياطي: EODHD، بميزانية افتراضية مقدارها 20 طلبًا يوميًا، مع تخزين مؤقت لتقليل استهلاك الخطة المجانية.
- تاريخ المؤشر المرجعي والبيانات الفعلية يظل رهينًا بما يتيحه المزود لكل رمز؛ لذلك يجب استخدام سجل التغطية وتاريخ أول/آخر سعر بدل افتراض اكتمال التاريخ.
- الأسعار المعدّلة قد تختلف عن الأسعار الخام؛ يجب مراعاة ذلك عند مقارنة نتائج تاريخية أو احتساب العائد.
- أسعار الصناديق المنشورة وقيم NAV لا تتوافر بالضرورة لكل صندوق أو لكل يوم. يظهر المصدر والتاريخ عند توفرهما، ولا ينبغي اعتبار القيمة المفقودة صفرًا أو سعرًا حديثًا.

### تحذير منهجي عن التاريخ

الاختبار على قائمة الأسهم الحالية فقط يعاني من **تحيز البقاء**: الشركات المشطوبة أو التي خرجت من السوق أو المؤشر قد لا تكون ممثلة في البيانات الحالية. لذلك لا تمثل نتائج الاختبار وحدها محاكاة كاملة لما كان يمكن معرفته في كل تاريخ تاريخي. كما أن أي اختبار لا يثبت تلقائيًا قابلية تحقيق نفس النتائج مستقبلًا.

## 4. التعلم الآلي والتعلم العميق

يستخدم `src/ml_model.py` نموذج Random Forest وشبكة عصبية متعددة الطبقات (MLP)، مع مزيج احتمالي بينهما. الهدف الحالي هو تقدير احتمال تجاوز عائد محدد خلال أفق افتراضي قدره 10 جلسات، مع مراعاة تكلفة التداول المحددة في الإعدادات.

الضوابط الحالية:
- تقسيم التدريب والتحقق زمنيًا حسب تاريخ الجلسة، لا تقسيم صفوف عشوائيًا.
- عزل فترة أفق التنبؤ قبل بداية التحقق لتقليل تداخل الملصقات وتسرب المعلومات.
- اشتراط حد أدنى من العينات وتنوع الهدف.
- مقارنة AUC وBrier بخط أساس، وتقليل أثر ML عندما لا يتجاوز شروط الجودة المضبوطة.
- النموذج لا يضمن اتجاه السعر، واحتمالاته تقديرات تاريخية وليست ضمانًا.

**حدود مهمة:** النموذج ليس نظام تعلم ذاتي مباشرًا يغيّر قراراته بعد كل صفقة. إعادة التدريب وتغيير الأوزان يحتاجان إلى تشغيل واختبارات منفصلة. لا تُعتبر الشبكة العصبية أفضل من النماذج الأبسط إلا إذا أثبت ذلك اختبار خارج العينة.

## 5. الفرص وإدارة المخاطر

محرك الإشارات في `src/signals.py` يجمع النقاط الفنية، حالة السوق، السيولة، التذبذب، وشروط عدد الفرص المسموح بها. توجد حدود منفصلة للشراء بحسب حالة السوق، ولا يلزم أن يصدر النظام توصية كل يوم.

- `BUY`: اجتازت الإشارة الشروط الفنية والسوقية والسيولة وبوابة الشريعة.
- `WATCH`: مرشح للمراقبة أو لم يستوفِ شرطًا واحدًا أو أكثر.
- عدم وجود BUY ليس عطلًا بحد ذاته؛ راجع أسباب الاستبعاد وحالة البيانات أولًا.
- مستويات الوقف والأهداف حسابات سيناريو مبنية على قواعد النظام، وليست ضمانًا لتنفيذ الصفقة بالسعر المحدد.
- `src/backtest.py` وملفات `data/backtest/` تقيسان الأداء التاريخي. يجب قراءة النتائج مع تكاليف التداول، وتغطية البيانات، وتحيز البقاء، واحتمال تغير النظام السوقي.

## 6. الصناديق

`src/funds.py` يحتوي مسارًا منفصلًا لصناديق الأسهم المتوافقة مع الشريعة وصناديق الذهب. يحاول جلب قيم NAV المنشورة من صفحة عامة واحدة ومطابقة الأسماء/الأكواد المعروفة، كما يتابع سلسلة الذهب من مزود الأسعار المتاح.

- مطابقة الاسم لا تعني أن NAV متاح أو محدث لكل صندوق؛ يجب فحص `nav_date` و`price_source`.
- صندوق الذهب وصندوق الأسهم ليسا سهمًا عاديًا؛ ينبغي عرض الرسوم، وتاريخ التقييم، وطبيعة الأصل عند توفر المعلومات.
- أي صندوق جديد يجب إضافته بعد مراجعة اسمه ورمزه ومصدر سعره وتصنيفه الشرعي، دون استنتاج التوافق من الاسم وحده.

## 7. التشغيل اليومي والاختبارات

ملف `.github/workflows/egx-daily-report.yml` يشغّل اختبارات Offline عند تغييرات الكود، ويشغّل التقرير الفعلي عبر الجدولة أو التشغيل اليدوي. هذا الفصل يمنع كل تعديل برمجي من إرسال رسالة Telegram تجريبية أو استهلاك حصة API.

آخر تحقق موثق وقت كتابة هذه الصفحة:
- GitHub Actions run: [39118066491](https://github.com/MedhatCoding/Egx-ai-analysis-/actions/runs/39118066491) — نجحت اختبارات المحرك دون اتصال.
- تشغيل الاختبارات لا يثبت أن مزودي الأسعار متاحون لحظيًا أو أن رسالة Telegram أُرسلت؛ هذان يحتاجان إلى تشغيل فعلي ونتيجة واضحة في سجلات الخطوات.

### التشغيل المحلي

```bash
pip install -r requirements-job.txt
python tests/test_engine.py
```

للتشغيل الفعلي، استخدم سير عمل GitHub Actions اليدوي بعد مراجعة المدخلات والأسرار. لا تضع مفاتيح API أو بيانات المحفظة في ملفات التوثيق أو داخل Git.

## 8. أولويات التطوير التالية

1. توثيق تاريخ أول وآخر جلسة ونسبة التغطية لكل رمز في الواجهة.
2. توفير قائمة تاريخية لمكونات EGX33/الكون الشرعي حسب كل تاريخ، لتقليل تحيز البقاء.
3. اختبار Walk-forward متكرر على فترات زمنية متعددة، مع تكاليف تداول وانزلاق سيعكس سيولة EGX.
4. قياس أداء النموذج حسب حالة السوق وحجم السيولة، وإظهار عدم اليقين وحجم العينة.
5. اختبار مستقل لمطابقة NAV للصناديق وتاريخ آخر قيمة لكل صندوق.
6. إضافة سجل أداء إشارات غير قابل للتعديل بأثر رجعي، يلتقط بيانات الإشارة كما كانت عند صدورها.

هذه أولويات معلنة وليست ادعاءً بأن جميعها اكتملت بالفعل.
